# Demo Scenario and Pitch Flow

## Scenario purpose

This fictional scenario is the **single coherent story** behind the sales demo. Every screen, account signal, outreach action, audit entry, and human handoff should reinforce this story. It is deliberately realistic enough to sell the product experience, but it uses no real client, contact, transaction, message, or pricing data.

## Fictional distributor

| Field | Demo value |
| --- | --- |
| **Name** | Harborline Beverage Distribution |
| **Profile** | Fictional regional wine, spirits, and RTD distributor serving independent retailers. |
| **Operating story** | A lean sales organization with a strong relationship-led culture and a need to cover more accounts consistently. |
| **Team shown in demo** | 18 account representatives, 642 active retail accounts, 1 operations manager. |
| **Demo promise** | “Make sure no valuable account moment gets lost while the rep stays in control of the relationship.” |

## Primary account story

| Field | Demo value |
| --- | --- |
| **Retail account** | Juniper Bottle House |
| **Account profile** | Fictional independent bottle shop; preferred outreach is rep-approved email. |
| **Primary contact** | Lina Cho, Beverage Buyer |
| **Assigned rep** | Renee Lewis |
| **Segment** | High-opportunity neighborhood account |
| **Primary product** | Solara Coastal Spritz — Citrus 4-pack |
| **Signal** | No reorder for 38 days against a typical 21-day reorder cadence. |
| **Why it matters** | The account ordered 30 cases across the prior three cycles and is now outside its expected cadence. |
| **Recommended action** | Review an approved, relationship-led availability check—not a promotional offer. |

## The control story

The system does not “decide to sell” or invent an offer. It notices a visible operating signal, links the signal to a named account and rep, presents approved outreach, preserves the evidence, and returns an ambiguous commercial request to the human account owner.

| Step | What the system shows | What the seller says |
| --- | --- | --- |
| **Signal** | Juniper Bottle House is marked at reorder risk because its 38-day gap exceeds its 21-day expected cadence. | “The manager does not start with a giant spreadsheet. They see the accounts that require attention and why.” |
| **Context** | Prior case volumes, product history, account preference, and Renee as accountable owner. | “This is not a generic blast. The recommendation is based on the account’s operating history and stays connected to the rep.” |
| **Controlled outreach** | An approved email template marked eligible and ready for Renee’s review. | “The system is preparing a controlled touchpoint; the distributor still owns the message and the rule.” |
| **Audit evidence** | A timestamped event trail showing signal detected, template prepared, and user action. | “Every action is visible. You can see what happened, why it happened, and who owns the next move.” |
| **Human handoff** | A fictional reply asks about a prior deal. The system escalates the thread to Renee. | “This is where the product earns trust. It does not make up pricing or negotiate; it gives the relationship back to the rep.” |

## The ten-minute live pitch

| Minute | Seller action | Buyer takeaway |
| --- | --- | --- |
| **0:00–1:00** | Open the Harborline command center. Point to account coverage, active signals, and the priority queue. | “This looks like an operating system, not an AI toy.” |
| **1:00–2:30** | Select Juniper Bottle House from the reorder-risk queue. | “I can immediately see which account needs attention.” |
| **2:30–4:00** | Explain the reorder signal, expected cadence, prior order pattern, product, and assigned rep. | “The system has a clear reason for the recommendation.” |
| **4:00–6:00** | Open the approved outreach preview and show the eligible/controlled status. | “My team keeps control of communication and tone.” |
| **6:00–7:30** | Run the simulated send/approval action and open the audit trail. | “The workflow is traceable and manager-visible.” |
| **7:30–8:30** | Reveal the fictional “last month’s deal” reply and escalate it to Renee. | “The product extends the rep instead of replacing the relationship.” |
| **8:30–10:00** | Show the implementation-readiness message: the same flow is configured with the client’s accounts, users, templates, and approved channel. | “This can become our system after implementation.” |

## Required demo states

1. **Command center:** A premium manager dashboard with active account risks, action queue, and rep ownership.
2. **Account detail:** Juniper Bottle House context, cadence signal, order pattern, account owner, and recommended action.
3. **Outreach review:** Controlled/eligible message preview with no price, promotion, or unsupported client claim.
4. **Audit timeline:** A chronological record of signal, review, send simulation, reply, and escalation.
5. **Rep handoff:** Renee owns the ambiguous reply and the clear next step.
6. **Reset:** The demo returns to its opening state without persistent actions or live delivery.

## Second account story — allocation review

The second story proves that Harborline Command does more than notice missed reorders. It can help a distributor prepare a higher-control account moment while keeping commercial judgment with the responsible representative.

| Field | Demo value |
| --- | --- |
| **Retail account** | Fleetwood Spirits |
| **Account profile** | Fictional specialty spirits retailer in Hoboken, NJ; previously responsive to small-batch allocation notices. |
| **Assigned rep** | Marcus Vale |
| **Product** | Nila Reserve Gin · 750ml |
| **Signal** | A limited 12-case allocation is available for a defined review window. |
| **Why Fleetwood is surfaced** | The account received six cases in the prior comparable allocation and has a verified category fit. |
| **Recommended action** | Marcus reviews a neutral availability-check message. The workflow cannot offer a price, promise quantity, or confirm a commercial term. |
| **Human-control moment** | Marcus must review any interest, quantity question, or deal request before response. |

### Seller framing

> “The workflow is not deciding who receives inventory or what the commercial terms should be. It is bringing the right account moment to the rep with the evidence, a controlled message, and a visible owner.”

## Client configuration model

The configuration screen should make the implementation path credible without presenting a generic settings page. It shows that the same operating experience becomes the client’s system through five deliberate configuration layers.

| Layer | What a buyer sees | Why it matters |
| --- | --- | --- |
| **Operating records** | Account, product, order-history, and ownership inputs. | The client understands that recommendations are grounded in their own operating data. |
| **Coverage rules** | Cadence thresholds, allocation windows, risk indicators, and excluded accounts. | The client controls what creates a signal. |
| **Communication controls** | Approved templates, preferred channels, eligibility, and review requirements. | The client controls what may be prepared or delivered. |
| **Human ownership** | Rep routing, manager visibility, and escalation handling. | The client sees that accountability remains explicit. |
| **Evidence policy** | Audit event schema, retention, and management visibility. | The client sees a controlled implementation path rather than a black box. |

## Non-negotiable copy rules

| Use language like | Avoid language like |
| --- | --- |
| “reorder signal,” “approved outreach,” “account owner,” “review,” “audit trail,” and “rep handoff” | “AI closed the sale,” “automatic deal,” “guaranteed revenue,” “real-time client data,” or “compliance approved” |
| “Would you like to review availability?” | “We can honor a special price” or any made-up promotional term. |
| “The product is configured to your policies during implementation.” | “This is already connected to your ERP/CRM.” |

## Build acceptance test

The first demo milestone passes when a sales partner can show the six required states in order, complete the flow in under ten minutes without explaining placeholder data, and truthfully state that it is a configured product experience awaiting client-specific implementation.
